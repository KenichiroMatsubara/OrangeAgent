# Let an outside agent do what Operator Chat does

The CLI and the MCP Server exist so that an outside agent can do everything Operator Chat does. An Access Token therefore holds what an Operator Token holds: the Automation Inbox's Google grant, the Account's Skills, its Memory, the web, and the Account's browser. Both keys are one run outside OrangeAgent (`OUTSIDE_RUN` in `packages/domain/src/tools.ts`). A tool added for Operator Chat reaches both unless it needs something only a run OrangeAgent drives can be lent: the files a conversation wrote, a Run Token, or the environment `code.run` lends. Each MCP call arrives as its own request, so a key's browser is not closed when a call ends: `key_browsers` names its Browser Run session and page, and the next call reconnects to them, as a sign-in on the ブラウザ screen does. An Access Token is still narrowed by its Tool Grant, which starts with every tool checked, and by the one Contact List it may reach. Its Suppression Window still holds a repeated write.

This reverses the rule from ADR 0152 that kept the mailbox, the calendar, the Drive, Tasks, the Skills, and the Memory away from every Access Token. That rule made the screen offer five tools. Every new tool then passed outside agents by without anyone choosing that. The person who issues a key decides what it may do, on the screen where they issue it.
