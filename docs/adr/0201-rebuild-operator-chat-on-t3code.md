# Rebuild Operator Chat on t3code's chat

Operator Chat ("AI に聞く") is rebuilt from the chat of t3code (`pingdotgg/t3code`, MIT), an open-source control plane for coding agents whose main product is its interface. We copy its React timeline, tool inspector, approval row, composer, queued messages, and subagent card into the repository once (`packages/t3chat`), keep its licence notice, and own the copy from then on: we never merge upstream again, because its contracts change incompatibly about once a week. We take its shape of a turn as well: an assistant turn is an ordered list of items (text, reasoning, tool call, approval request, question, subagent, error), each with its own status, and a conversation is a log of events with a sequence number per conversation, so a client that reconnects asks for the events after the last one it saw, or a fresh snapshot. We take neither its server nor its transport. Its server is a Node process that drives coding agents installed on a person's computer, and its client speaks Effect RPC over a WebSocket. FlareChat keeps its own engine (`turns.ts`) and serves the events from its own Durable Object.

The choice was made for the chat alone, ignoring the other screens, the current framework, and the cost of moving. We prototyped both candidates on the same Japanese conversation, which held a table, reasoning, a failed tool, a subagent, and two writes waiting for approval. OpenCode's interface is a SolidJS side of a product whose centre is its terminal UI and engine. Its timeline package has no approval prompt; that lives in the app. It shows a tool without a dedicated view as one truncated line, without arrays or the result. It deliberately drops the files and images a tool returns. Most of FlareChat's tools are exactly such tools. t3code rendered every part natively. It shows a tool's arguments and result, puts approvals inline with allow once, always allow, and decline, folds finished turns, groups subagents, and ships a complete Japanese dictionary and IME-safe sending. OpenHands and building the interface from scratch were rejected as well: OpenHands has yes/no approvals, a separately versioned server, and a codebase that is mostly not chat; building from scratch would mean writing all of that polish ourselves.

## Consequences

- The copied code keeps its own conventions (Tailwind, Base UI, Effect atoms, multi-word file names) and is exempt from this repository's style rules. Anything it does not need for chat is deleted from the copy: git, worktrees, terminals, diff panels, pull requests, the provider and model pickers, and office and PDF viewers.
- Sibling alternatives of an answer are dropped. Editing an earlier message rewinds the conversation, and "continue from here" forks a new conversation. A stored conversation that has branches stays readable, one branch at a time.
- Approval is a mode a person picks per conversation in the composer: read-only, ask before every write, auto, or unrestricted. Opening and reading a page in the browser are not asked about; clicking, typing, choosing, and pressing a key are. A tool a person has once allowed always is not asked about again. In auto, Perplexity's Decider model, called through OpenRouter, judges each write. It fails closed: when the judgement fails, the person is asked. Auto exists only where the deployment holds an OpenRouter key; without one it is not offered, and a conversation kept in auto is unrestricted. New conversations start in the mode of the person's latest conversation, and in unrestricted when there is none. Automations are unattended and keep their Execution Modes unchanged.
- A write waiting for approval is stored and survives the Durable Object being evicted, which neither t3code nor OpenCode does.
- Web Push and a Service Worker are FlareChat's own; neither candidate has them.
